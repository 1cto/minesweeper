# The live site is tested after each deploy, and the Allure report is published beside it on Pages

After each deploy of `main`, the Deploy workflow runs the Playwright tests tagged `@prod` against the live site and publishes an Allure report at `/minesweeper/reports/` on the same GitHub Pages site. A failure fails the workflow, and the report is published either way.

Only tests that open the game at its plain address carry the tag. The public build has no test-only `?layout=` parameter (`pnpm check:no-test-hooks` keeps it out), so a test that fixes the Layout cannot run against the live site. Without a fixed Layout, the Mines on the live site are random, so such a test would fail or pass by chance. The tagged tests (the window, the menus and dialogs, the scale rule, mouse behaviour that needs no Layout, and the check that every asset loads under `/minesweeper/`) passed 5 runs out of 5 against a public build when the tag was introduced. A new test gets the tag only if it opens the game with `page.goto("./")` and needs no Layout or test hook. The full suite still runs on the test build in CI on every pull request.

A Pages deployment from Actions replaces the whole site, so a report cannot be deployed on its own without removing the game, and an earlier report does not survive the next deploy. The workflow therefore deploys twice: first the site, then, after the tests, the same files with the report added under `reports/`. Allure's `history.jsonl` is fetched from the published report before the first deploy and published again with the new report. This keeps the trend and the flaky marks without a separate branch or storage. Only the latest report is kept.

Considered: a `gh-pages`-style branch holding every report (the repository would grow with each run, and Pages would have to be switched from Actions deployment to a branch); Actions caches for the history (evicted after 7 days without use, so a quiet week loses the trend); running every e2e test against the live site (about 40 of them fail without `?layout=`).
